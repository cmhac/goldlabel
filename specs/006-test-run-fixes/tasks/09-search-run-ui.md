# 09 — Search: centred first run and the handoff results grids

Spec: item 10, Q7. Depends on 07 (the panel gap rule). Design source: `../../004-history-and-redo/design/design_handoff_hunches_tui/reference/ui_kits/tui-rail/Search.jsx` and the Search section of `../../003-tui-redesign/design/README.md`; read both before starting.

**Do: states** (`screens/search.py`). Today the top row and both results panels are always mounted and `#results` is only dimmed (`-inactive`). Make `SearchScreen` have two modes, chosen in `refresh_state` from "has a search produced results" (`candidates.jsonl` exists):
- **First-run mode** (no `candidates.jsonl`): `#results` is `display: none`; the Run block is centred horizontally and vertically in the content area. Contents by state: seeds not approved: the disabled `Run search  r` button with "Seeds are not approved yet." beneath; approved: the button; first run in progress: "Searching…" with the progress (`LabelBar` `4/12  <seed>`, or the elapsed/rows line for the pgvector one-query mode) and Stop where it exists today; failed or stopped: the button again with the error ("Search failed: …", the "Fix:" line) or "Search stopped." beneath, centred. Prefer re-laying-out the existing widgets with a screen class (e.g. `-first`: `#top` becomes a centred vertical block, notices centred beneath) over adding a second progress widget; if `RunIndicator` (`screens/progress.py`) fits more cheaply (it already centres a title, bar, counts, status and button), use it and add the missing `run` kind to its `BUTTONS`. Either way keep the ids the existing tests and bindings use (`#run`, `#stop`, `r`, `x`) or update the tests.
- **Results mode** (`candidates.jsonl` exists, including on opening a project with one): the handoff layout. Top row (button, status, similarity-independent notices), then both panels. A rerun in progress keeps today's top-row progress bar and dimmed panels; stale results (seeds or embedding model changed) show normally with the existing banners; the rerun confirm is unchanged. After a successful first run, switch to results mode.

**Do: grids** (pure functions in `screens/search.py`, tested directly; keep the existing `bar()` helper)
- `band_rows(counts, width)`: **Candidates by similarity**. A muted header row `Similarity` … `Candidates`; then one row per band: label column 11 wide (strong colour, `0.6–0.625`, the last band `0.75+`), 2-cell gap, a bar column filling the remaining width but capped at 40 cells (bar scaled to the largest band), 2-cell gap, a count column 11 wide, right-aligned, bold with thousands separators, faint and not bold when 0. Panel subtitle `N candidates` (retitle as today).
- `seed_rows(top, width)`: **Top seeds**. Per row: rank (3 wide, right-aligned, faint), count (7 wide, right-aligned, bold, separators), bar (12 cells, `$primary`; row 1 `$accent`), then the seed text filling the remaining width, truncated with `…`. The similarity select in the subtitle and `candidates.top_seeds` are unchanged. Empty result keeps the muted "No items at or above this similarity." line.
- The widgets render these into `Static`s (or `DataTable`s per the AGENTS.md notes, if easier); widths come from the panel's actual width and are recomputed on resize, so rows line up at 80×24 and 120×36. One blank row between the two panels, the same gap rule as task 07.

**Tests (red first)**
- `band_rows` and `seed_rows` against hand-written expected text for a small known input at two widths (including a 0 count, a count over 999 for the separator, a long seed that truncates, and the 40-cell bar cap at a wide width).
- States (Pilot, stub embedder): never run + not approved; never run + approved (button `region` centred in the content area within one cell and one row; `#results` not displayed); progress during the first run (stub embedder waiting on an `asyncio.Event`); failure and stop messages centred; after the run, results displayed and the top row present; opening a project that already has candidates goes straight to results mode; stale seeds still show results plus the banner; rerun confirm unchanged.
- `tests/test_sizes.py`: first-run and results states at all three sizes, nothing clipped.

**Not in this task**: navigation while a search runs (10).
