# 11 — Clickable rail

Spec: item 11, point 1. Depends on 10 (navigation must not stop runs).

**Do** (`app.py`)
- **Verify the mechanism** in Textual 8.2.8 before coding: the rail is one `Static` built from markup by `StatusHeader.refresh_rail` (`row()` and `plain()` helpers). Textual's content markup supports `[@click=action]text[/]` (https://textual.textualize.io/guide/content/); check it works around a whole rail row built from `markup(...)` pieces (nested style tags, `$variables`, the `on $panel` background), and that the click lands on the widget's action namespace (`app.` prefix). The fallback is `on_click` mapping `event.y` to the line index (the lines list in `refresh_rail` is the single source of truth for which line is which row). Choose the smaller; record the result in the spec under "Verified in task 11".
- Every row does what its key does: the nine stages (`goto_stage`), `Projects` (F4 `action_projects`), `Project settings` (F3), `System settings` (F5), `History` (F8) and, when shown, `↻ Redo plan` (F9). Route clicks through the **same `action_*` methods and their `check_action` guards**, so a click that its key could not perform is ignored (History while an editor draft is open, any click while a modal is on top).
- **Overlays**: the rail is also shown on Projects, Project settings and System settings (`stage_name` screens). Today `goto_stage` uses `switch_screen`, which on an overlay would replace the overlay instead of the stage screen underneath. Clicking a stage from an overlay must pop the overlay screens down to the base stage screen first and then go to the stage; clicking another destination while on one overlay replaces it (pop, then push); clicking the current stage or the current overlay does nothing. Project settings with unsaved changes: check how `editing`/drafts are handled today for F3/F4 navigation and do the same (do not add a new confirm unless the key path has one).
- Below 100 columns there are no rail rows; keys remain the only route (unchanged).

**Tests (red first, Pilot at 100×30 and 120×36)**: compute each row's line index from the same list the rail renders (not hard-coded numbers that rot) and click it with `pilot.click(StatusHeader, offset=(x, y))`: each stage opens that stage; from Projects/Settings/System settings clicking a stage lands on that stage with no leftover overlay (assert `len(app.screen_stack)`); clicking Projects/Settings/System/History opens the same screen as the key; clicking the current stage does nothing; clicking History while a seed editor is open does nothing; with a modal on top clicks do nothing; clicking away from a running Search keeps it running (builds on task 10's test); Redo plan row appears only when something is stale and opens the plan.
