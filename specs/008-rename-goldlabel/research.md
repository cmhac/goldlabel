# Research: Rename the library to goldlabel

Facts were checked against the repository on 2026-10-30 (and PyPI where stated).

## R1. Where the old name lives

- `git ls-files | grep -c hunches` finds 154 tracked paths with the name in the path; most (about
  120) are the 004 design handoff under `specs/`, which stays as history. Outside `specs/`: the
  package `src/hunches/` (all modules and `web/*`), `skills/hunches/`, `.kiro/steering/hunches.md`.
- File contents: 194 tracked files mention it. Outside `specs/` the heavy ones are `README.md`,
  `AGENTS.md`, the tests (imports, fixtures, the drift tests), `skills/hunches/**`,
  `docs/agent-instructions.md`, the examples, `.github/workflows/ci.yml`, `.gitignore`,
  `pyproject.toml`, the two plugin manifests plus the marketplace manifest, `uv.lock`, and
  `.specify/memory/constitution.md`.
- Persisted or wire-visible strings: env vars `HUNCHES_DIR`, `HUNCHES_PG_URL`,
  `HUNCHES_TEST_PG_URL` (`HUNCHES_HOME` exists only in the 002 history specs); default directory
  `.hunches`; the page header `X-Hunches-Token` (`_label.py`, `web/app.js`, four tests); the gold
  row stamp `hunches-ui` (`_label.py`, `gold.py`, `evaluation.py`); the evaluation-log key
  `"hunches"` (version); Postgres cursor names `hunches_pairs|texts|items`; the page `<title>`;
  pip hints `pip install hunches[pg]` etc. in `ImportError` messages.

## R2. The legacy stamp is the one real compatibility risk

`GoldSet._summary` (`gold.py:68`) and the provenance count in `evaluation.py:178` use a fixed
dict `{"hunches-ui", "imported", "unstamped"}`; any other `labelled_by` value falls into
"unstamped". A blind rename to `goldlabel-ui` would therefore silently reclassify every existing
page-made label as unstamped, with no error. Decision: the new stamp is `goldlabel-ui`; one tiny
helper maps the legacy `hunches-ui` onto it when counting. Rows are never rewritten, and the
helper is the single place the old stamp appears in `src/`.

Alternatives: keep writing `hunches-ui` forever (leaves the old name in the product; rejected);
migrate existing files (forbidden by the gold rule: never edit a gold file); count both keys
separately in the summary (more output, same meaning; rejected).

## R3. The evaluation log needs no code

`read_log` is `json.loads` per line into a list; nothing indexes the `"hunches"` key (grep). New
lines write `"goldlabel"`; old lines load unchanged. FR-007 is met by a test, not a shim.

## R4. Environment variables and the default directory

`settings.py:9` reads `HUNCHES_DIR` then `.hunches`; `search.py:217` has the default
`url_env: str = "HUNCHES_PG_URL"`; CI and `test_pg_integration.py` read `HUNCHES_TEST_PG_URL`.
Plain rename, no fallback (constitution V forbids reading things behind the caller's back, and the
spec skips shims). Silent-data risk: a user with an old `.hunches/` gets an empty `.goldlabel/`
(cache re-pays embedding/model cost, evals log restarts). Mitigation is the README migration note
(FR-013); it is a cost, not a correctness, problem because gold files live where the user put them.

## R5. The gold rule and the constitution

`src/goldlabel/gold_rule.md` and the constitution both contain the name. The constitution says the
rule "MUST NOT be reworded" and that amendments need `/speckit-constitution` and the user's
approval. A name-only substitution weakens nothing (PATCH under the constitution's own versioning)
but is still an amendment. Decision: the rename implementation is gated on that approval (plan
Constitution Check, spec FR-011). The agent does not hand-edit either file in a normal task; the
amendment step runs the skill, then the drift tests print any copy to paste.

## R6. Mechanics that keep the diff small

- `git mv` the three paths, then one scripted replacement over tracked files, longest token first:
  `HUNCHES_`→`GOLDLABEL_`, `X-Hunches-Token`→`X-Goldlabel-Token`, `hunches-ui`→`goldlabel-ui`,
  `hunches`→`goldlabel`, then the docs/test alias `\bhn\b`→`gl`. Excluded: `specs/` (history, bar
  this feature's folder), `tests/fixtures/pre006/README.md`, `uv.lock`, `skills-lock.json`, `.git`.
- `uv.lock` is regenerated by `uv lock` (the package's own entry changes name), never hand-edited.
- Ruff's import sorting may reorder `goldlabel` imports relative to third-party/first-party groups;
  `uv run ruff check --fix` and `ruff format` settle it. The diff is then reviewed by eye for `hn`
  false positives in prose.
- The web assets contain the name only in the title/header strings; `app.css` is built output with
  no name, so Tailwind is not rebuilt.
- `uv build` must still ship `goldlabel/web/*` and `goldlabel/gold_rule.md` (uv_build finds the
  module by project name, so the directory and the distribution name must match: they do).

## R7. Names

- PyPI: `https://pypi.org/pypi/goldlabel/json` returned 404 on 2026-10-30 (unregistered);
  `https://pypi.org/pypi/hunches/json` returned 200 (the old name belongs to someone on PyPI).
  Not a reservation; publishing is the user's.
- The GitHub API for `cmhac/goldlabel` was not reachable from this sandbox (403 from the proxy), so
  whether the repository has been renamed is unknown. Manifests get the new URL; renaming the
  repository is the user's (spec Assumptions) and should happen before or with the merge, or the
  README install commands point at a missing repository.
- Agent plugin install commands change shape (`goldlabel@goldlabel`); the ones the README marks
  unverified stay unverified and are in the human checklist.

## R8. Tests to add (red first)

1. `tests/test_no_old_name.py`: walks `git ls-files`, strips the allowlist (FR-009), fails on any
   `hunches` left (case-insensitive). Red before the rename because everything fails.
2. Legacy stamp: a gold fixture built by hand with rows stamped `hunches-ui` summarises as
   labelled through the page, the file's bytes are unchanged (edit `test_gold_rule.py`'s summary
   assertion and add one case in `test_gold.py`).
3. Old log line: a hand-written `evals.jsonl` line with `"hunches": "0.1.0"` loads (`test_evaluation.py`).
4. Rule equality (SC-003): the new `gold_rule.md` equals the old text with the name replaced; the
   old text is read from git (`git show HEAD~:...` is fragile), so the test pins the expected full
   text inline instead of deriving it from the code under test, which is the constitution's rule
   for expectations anyway. Existing drift tests cover the copies.
5. Existing tests change by the mechanical replacement only (`hunches`→`goldlabel`, `hn`→`gl`),
   which is the green half of the red/green cycle.
